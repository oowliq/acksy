# ADR 0001: Портируемый SQL через sqlx вместо sqlc

- Статус: принято
- Дата: 2026-11-09

## Контекст

Acksy одинаково поддерживает SQLite и PostgreSQL (инвариант 5 в AGENTS.md). Изначально планировался `sqlc`, но:

- для Postgres `sqlc` разбирает SQL через `pg_query_go`, а это требует CGO;
- для двух диалектов пришлось бы держать два набора запросов, два сгенерированных пакета и адаптеры к общему интерфейсу. Каждый запрос писался бы дважды.

## Решение

- Один набор запросов в `internal/store/*.go`, написанный на подмножестве SQL, общем для SQLite (3.35+) и PostgreSQL. В запросах используются плейсхолдеры `?`; для Postgres `sqlx.Rebind` превращает их в `$N`.
- Время хранится как Unix-миллисекунды (`INTEGER` / `BIGINT`), JSON — как `TEXT`, булевых колонок нет (вместо них nullable-таймстемпы вида `read_at`).
- Допустимые конструкции: `ON CONFLICT … DO UPDATE`, частичные индексы, `RETURNING`, `COALESCE`.
- Запрещены диалектные конструкции: `::cast`, `ILIKE`, `NOW()`, `jsonb`-операторы, `AUTOINCREMENT`/`SERIAL`. Время передаётся параметром из сервиса.
- Миграции по-прежнему ведутся отдельно для каждого диалекта (`migrations/{sqlite,postgres}`): различаются только типы.
- Корректность на обоих диалектах обеспечивает контрактный набор тестов `internal/store/store_test.go`. Локально он гоняется на SQLite, с `ACKSY_TEST_POSTGRES_URL` — на Postgres; в CI — на обоих.

## Последствия

- Генерации кода и CGO нет, запрос пишется один раз.
- Компилятор не проверяет соответствие запросов схеме. Эту защиту дают контрактные тесты, поэтому новый запрос без теста в `store_test.go` не принимается.
- Если понадобится диалектная оптимизация (например, полнотекстовый поиск), её реализуют отдельным методом с ветвлением по `queries.dialect` и тестом на обоих диалектах.
