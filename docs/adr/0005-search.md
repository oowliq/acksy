# ADR 0005: Поиск по уведомлениям

- Статус: принято
- Дата: 2026-11-09

## Контекст

M7 добавляет поиск в инбоксе. Он должен работать одинаково на SQLite и Postgres (ADR 0001), находить слова в любом регистре, в том числе кириллицу, и сочетаться с остальными фильтрами списка и с курсорной пагинацией. Встроенные средства СУБД расходятся: в SQLite `lower()` и `LIKE` без учёта регистра понимают только ASCII, а полнотекстовый поиск у них разный (FTS5 и `tsvector`).

## Решение

- **Отдельная колонка `notifications.search_text`.**
  - В ней лежат заголовок, тело (сырой markdown) и теги через `domain.SearchText`: нижний регистр по правилам Unicode, пробелы схлопнуты.
  - Регистр понижается в Go, поэтому результат не зависит от СУБД.
  - Store пишет колонку при каждой вставке и при повторе по `dedup_key`.
  - Сырой markdown выбран, чтобы URL из ссылок тоже находились, а разметка не мешает поиску подстроки.
- **Запрос** `q` (не длиннее 200 символов, не больше 8 слов) разбивается на слова, и каждое слово даёт условие `search_text LIKE '%слово%' ESCAPE '\'`. Совпасть должны все слова. `%`, `_` и `\` из ввода экранируются. Запрос один на оба диалекта.
- **Порядок и пагинация** не меняются: новые сверху, курсор `before`. Ранжирования нет.
- **Старые записи** заполняет Go-миграция 10, общая для обоих диалектов. Сделать это в SQL нельзя, потому что `lower()` в SQLite не понимает кириллицу.
- **Тот же фильтр** принимает bulk-запрос (`q`, `min_priority`). Поэтому «Mark all read» во время поиска отмечает ровно найденное.

## Последствия

- Поиск полностью сканирует уведомления пользователя: индекс `(user_id, id)` сужает выборку до одного пользователя, но `LIKE '%…%'` индексом не ускоряется. Для домашней установки (тысячи и десятки тысяч уведомлений на пользователя, retention их подрезает) это миллисекунды.
- Нет морфологии и ранжирования. Запрос «бэкап» найдёт «бэкапы», потому что это поиск подстроки, а запрос «бэкапы» не найдёт «бэкап».
- Колонка увеличивает размер строки примерно на длину заголовка и тела.
- **Когда пересматривать.** Если список с `q` станет заметно медленным или понадобятся ранжирование и морфология, надо добавить полнотекстовый индекс для каждого диалекта за общим интерфейсом store и написать новый ADR вместо этого.
