# ADR 0004: Retention уведомлений

- Статус: принято
- Дата: 2026-11-09

## Контекст

Уведомления хранились вечно, и база росла без ограничений. README обещал TTL и лимиты на уровне пользователя, топика и приоритета. Нужно было решить, где задаются правила, что происходит с непрочитанными и как удаление видят открытые клиенты.

## Решение

- **Два уровня правил.**
  - **Инстанс** (конфиг `retention`):
    - `read_ttl` для прочитанных и архивных, по умолчанию 90 дней;
    - `read_ttl_by_priority` для отдельных приоритетов;
    - `unread_ttl`, по умолчанию выключен;
    - `max_per_user`, по умолчанию 10 000.
  - **Топик**, задаёт владелец: `retention_days` заменяет TTL прочитанных для уведомлений топика, `max_notifications` ограничивает копию каждого участника. Порядок старшинства: топик, затем приоритет, затем общий срок. Пользовательского уровня нет, чтобы не плодить три слоя правил.
- **Непрочитанное не исчезает молча.** Отдельный `unread_ttl` выключен по умолчанию. Лимиты количества сначала вытесняют самые старые прочитанные и трогают непрочитанные, только если прочитанных не хватает.
- **Возраст считается от `updated_at`.** Это последнее изменение: публикация, повтор по dedup, прочтение, архивирование. Только что прочитанное старое уведомление живёт ещё полный срок.
- **Уведомления с истёкшим `expires_at`** уже скрыты. Они удаляются через сутки после истечения.
- **Удаление — это обычное bulk-удаление.** Оно идёт порциями по 500, в транзакции на пользователя, с событием `notifications.bulk` (`action: delete`) и следующим `seq` (инвариант 3). Открытые клиенты убирают элементы сразу, а после разрыва дочитывают удаление по `since`.
- **Выполняет уборщик `app` раз в час.** За один проход удаляется не больше 50 000 уведомлений, остальное доберут следующие проходы. Так долгий проход не держит базу. Если уборщик одновременно запустится на нескольких инстансах, это безопасно: повторное удаление ничего не делает.

## Последствия

- После обновления прочитанные уведомления старше 90 дней будут удалены первым проходом уборщика. Чтобы хранить всё, задайте `ACKSY_RETENTION_READ=0`.
- Лимит в 10 000 на пользователя может удалить и непрочитанные, если прочитанных не хватит. Это осознанная граница роста.
- Отложенные уведомления подчиняются тем же правилам, что и непрочитанные.
