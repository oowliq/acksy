# ADR 0006: Настройки OIDC в базе

- Статус: принято
- Дата: 2026-11-09
- Заменяет пункт ADR 0002 о настройке провайдера через `ACKSY_OIDC_*` и секцию `oidc:`.

## Контекст

В M7 админ должен настраивать вход через OIDC из веб-интерфейса, без правки env и без рестарта. Провайдер читался из конфига один раз при старте. Его использовали три места: вход по паролю (выключен или нет), сопоставление OIDC-входа с пользователями (автосоздание, роли из групп) и HTTP-маршруты (кнопка SSO, редирект, callback). Сервер может работать в нескольких инстансах за общим Redis.

## Решение

- **Источник истины — база.** Настройки лежат в `instance_settings` под ключом `oidc` в виде JSON `domain.OIDCSettings`. Правила проверки (`Validate`) находятся в домене.
- **Разовый импорт.** При старте, если ключа нет, а `ACKSY_OIDC_*` или `oidc:` заданы, значения импортируются в базу. Если ключ уже есть, env игнорируется, и в лог пишется предупреждение. Две конкурирующие системы настройки не нужны: env остаётся только как путь миграции.
- **Секрет клиента** хранится открытым текстом, как приватный VAPID-ключ: он нужен в открытом виде для обмена кода. API его только принимает. Ответы содержат лишь `client_secret_set`; отсутствие поля при сохранении оставляет прежний секрет, пустая строка удаляет. В логи секрет не пишется.
- **Снимок в сервисе.** `Service.SignIn` держит настройки и собранного провайдера в `atomic.Pointer`. Все потребители читают снимок. Через 15 секунд инстанс сверяет `updated_at` с базой и пересобирает снимок только при изменении; при ошибке чтения остаётся на старом. После сохранения снимок этого инстанса заменяется сразу. Брокер для этого не нужен: опрос — один индексированный запрос раз в 15 секунд.
- **Провайдера собирает фабрика** из `app`. Сервис не знает о сети: `auth.NewOIDCProvider` с HTTP-клиентом `netguard`. Частные адреса разрешены, потому что IdP в домашней сети — обычное дело, а URL задаёт только админ.
- **Доступ.** Читать и менять настройки может только админ из login-сессии, как управлять токенами: утёкший токен не должен менять способ входа.
- **Защита от потери доступа.** Отключить вход по паролю можно, только если у сохраняющего админа есть идентичность у этого issuer. Без OIDC вход по паролю выключить нельзя. Если провайдер пропал, команда `acksy oidc allow-password` (через сервис, с системным принципалом) включает вход по паролю обратно, и сервер подхватывает это за 15 секунд.
- **Проверка до сохранения.** `POST /settings/oidc/test` делает discovery по присланным настройкам и отвечает `{ok, error}`. Ошибка описывает только класс проблемы (недоступен, HTTP-статус, не JSON, нет нужных endpoint-ов, не совпал issuer) и никогда не содержит тела ответа: иначе через проверку можно было бы читать внутренние HTTP-сервисы. Issuer не может содержать query или fragment.
- **Настройки читаются вне транзакций.** `LoginOIDC` берёт снимок до `InTx`: перечитывание внутри транзакции ждало бы соединение, которое она сама держит (у SQLite оно одно).
- **Сбой чтения не открывает вход по паролю.** Если настройки при старте прочитать не удалось, вход по паролю считается выключенным до следующей успешной попытки.
- **Отвязка своей идентичности.** Если пароль не задан или вход по паролю выключен, нельзя отвязать последнюю свою идентичность у текущего провайдера.
- **Импорт из env без `ACKSY_BASE_URL`** останавливает старт с понятной ошибкой, как раньше это делала проверка конфига.

## Последствия

- `ACKSY_OIDC_*` больше не действуют после первого импорта. Кто деплоит через env, меняет OIDC в интерфейсе. Предупреждение в логе напоминает об этом при каждом старте, пока переменные заданы.
- Без `ACKSY_BASE_URL` включить OIDC нельзя: не из чего собрать redirect URL.
- Изменения доходят до других инстансов с задержкой до 15 секунд. На это время на разных инстансах может действовать разная конфигурация входа.
- Дамп базы содержит секрет клиента. Шифрование секретов в базе — отдельное решение на будущее.
- Маршруты `/auth/oidc/*` зарегистрированы всегда. При выключенном OIDC они перенаправляют на `/login?error=oidc_unavailable`.
